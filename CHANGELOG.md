# Changelog

## Unreleased

- **Tables with thousands of columns work:** a CSV file with 2,000 columns ran out of memory at once (Profile, Insights and Pivot together), and those tabs failed without saying why. Profile now reads as many rows as fit (about 4 million values: 2,000 rows for 2,000 columns) and makes its cards 60 at a time (**Show 60 More**), with **find a column** that takes patterns (`cpu_*`). Insights reads the columns' units once instead of for every value. If a tab still runs out of memory, it says so.
- **Pivot fields by pattern:** **find a field** takes `*` and `?` (`cpu_*`, `*_ms`), and **Add the 10 to: Values · Rows · Columns · Filters** puts every field shown in an area at once.
- **Pivot no longer breaks when switching views:** going from Table to Both (or Chart to Both) failed with "No such child: 1" and left the Pivot tab empty. Every switch between Table, Both and Chart now works.
- **Compare folders:** choose two folders (or zips) in the Compare tab: one table shows both sides, a row per file or folder with its size and time, = same, ≠ different, ◀ only left, ▶ only right; files of the same size compared byte by byte; Show the differences (at first), everything, or one kind, with counts; find a name; double-click two files to compare them. It only reads: nothing is copied or deleted.
- **Compare text and logs line by line:** files that aren't CSV now compare side by side in the Compare tab, as a code review shows them: matching lines on one row, a line only one file has facing an empty row, changed blocks blue, added green, removed gray, and the changed words within a line marked. F7 goes from change to change; ignore spaces or case; **mask times, numbers or IDs** so two runs of a job line up; fold unchanged stretches; » and « copy a change to the other side, with Undo and Save. A CSV comparison can be shown as text too (and back).
- **Three-way merge and git:** a merge shows yours, the result and theirs side by side; changes made on one side are taken, conflicts are red until resolved with » « (or both, or by hand); F7 goes from conflict to conflict; Save and Finish writes the result. **Help → Use Logsift with Git…** makes Logsift git's difftool and mergetool (`logsift --diff` and `logsift --merge`), in the open window if there is one.
- **Pivot tables and charts:** a CSV file gets a **Pivot** tab, as in a spreadsheet. Drag fields (or tick them) to **Rows**, **Columns**, **Values** and **Filters**: rows grouped (and groups inside groups, with subtotals), split across columns, values summed, counted, counted distinct, averaged, min or max, or shown as % of the total, the row or the column; times grouped by year, quarter, month, week, day, hour, minute, day of the week or hour of the day. Sort by a column's title, fold groups, a color scale, totals; a chart of it below (column, stacked, 100%, bar, line, area, pie, doughnut) with numbers on hover. Double-click a cell to see its rows in the log; copy or save the table as CSV and the chart as a picture. The layout is remembered per file. Every row is counted; it follows Matching only. Other logs with columns: right-click a column title → **Pivot Table and Chart**.
- **Starts on Windows Server 2016 and Windows 10 1607:** Logsift (and `logsift-mcp`) didn't start there, because Java's ZGC collector needs Windows 10 1803 or Server 2019. On Windows they now use the G1 collector, which runs on every Windows that Java 21 supports. macOS and Linux keep ZGC.
- **Coding agents (GitHub Copilot):** ask your coding agent about your logs, and it asks Logsift. `logsift-mcp`, which comes with Logsift, gives agents that support MCP (Copilot in VS Code, Visual Studio and JetBrains IDEs, Copilot CLI, and others) Logsift's analyses: a log's insights, exceptions by root cause, search, lines by number, top messages, durations and numbers, folder search (zips too), GC logs and thread dumps. Answers are short, with line numbers. Agents can only read, only under your home folder (or the folders you choose), never files that hold keys or passwords; secrets in answers are masked, and emails, IP addresses and your own patterns can be. **Settings → Agents** shows the exact setup for your agent, and **What Agents Asked…** lists every call.
- **Unexpected errors are easy to see and report:** the status bar shows **⚠ 2 errors** in amber while this session had any; click it (or **Help → Show Errors…**) for the list, the details, **Report on GitHub**, **Copy Details**, **Open errors.log** and **Clear**. Only the first error of a session (or running out of memory) opens a window. Bugs in background work (analyses, searches, merges, heap dumps) that used to leave a view silently not updating are now reported too; a file that can't be read or a server that doesn't answer still says so where it happens.
- **Compare CSV files by key:** **File → Compare Files…** (and **Compare Files…** on the start page) opens a **Compare** tab with a file browser on each side: folders, zips, and zips inside zips open like folders; type or paste a path, or drop a file on a side; then **Compare**. CSV and TSV files are compared as tables. Rows are matched by a key, wherever they are in each file: no key is chosen for you (rows are lined up in file order until you pick one); Logsift suggests one (a column, or two or three together, unique and filled in in both files; names like *id*, *…_id*, *code* first), says why, and **Use order_id as Key** uses it in one click. Adding or removing a key compares again at once, and chosen keys stay when files are dropped or swapped. **Not compared:** next to the keys, columns left out of the comparison (still shown, gray). Keys and columns to leave out are ticked in a list right below **Choose ▾**, with a filter for wide files; it compares again once, when the list closes; **Columns ▾** above the table only shows or hides columns, and pairs columns by hand. **Side by Side** shows the left file's rows next to the right file's, a key's rows on one line, empty where a file doesn't have the row; it shows every row, unchanged ones too, with changed rows tinted. A strip of marks by the scroll bar shows where the differences are (click to go there). The keys and the columns left out share one row; **Compare** stands out in the accent colour when options or the files chosen changed. A key value on more than one row of a file is listed under **key repeats** (never paired at random); hovering it in Show explains it with an example from the files, and it is offered only with a key. **Show** lists rows **added**, **removed**, **changed**, the **same** and **key repeats**, each with its count and colour; the files' names are one row right above the table (side by side, each over its table), with **Choose Files**, which shows the two file browsers in the table's place (**Close Files**, in the same spot, goes back); cells, rows and columns are selected as in a spreadsheet and **Ctrl+C** copies them as tab-separated text; two files dropped on the window ask whether to compare them or open each in a tab; **Changes per column** says how many rows changed in each column (click one to see them); a changed value shows as old → new (struck through in red, then green). Columns are matched by name (case and spaces don't count), can be paired by hand, and a column only one file has is mentioned once. Options: trim spaces, ignore case, numbers as numbers within a tolerance (absolute or %), empty = missing, and, without a key, rows lined up in file order or matched wherever they are. F7 / Shift+F7 go to the next and previous difference, search finds text in the results, a double-click opens the row's line in its file, and **Export** writes the differences as CSV or a short summary. Also **Compare** in a folder's or zip's tab with two files selected, and the compare button in a CSV tab's bar. Drop a file on the left or right half of a comparison to compare another one (two files: both). Files may differ in separator, encoding and line ends; quoted fields over several lines are fine. Two files of a million rows compare in about 2 seconds with about 50 MB of memory. Other files get a note in the tab for now: comparing text and logs line by line comes next.
- **Compare With… is now Compare Logs by Message…** (still Ctrl+Shift+D), so it isn't mistaken for comparing files row by row.
- **Open Folder:** **File → Open Folder…** (and the start page's Open Folder…) shows a folder's files in a tab, as a tree with sizes, like a zip's tab: filter by name, open files, **Merge by Time** (`.gz` unpacked first), **Find in all files** (Ctrl+F there; a folder search), and **Refresh**. Big folders are listed in the background, the first 20,000 files. Dropping a folder or **Open with Logsift** on a folder now opens this tab instead of a search; **Search in Folder…** (Ctrl+Shift+F) is on the start page under the buttons.
- **Middle click closes a tab:** a middle click on a tab closes it, as its ✕ does (what the log remembers is saved). In Find results, a middle click on a search's header closes that search.
- **Check for updates behind a company proxy:** the update check failed with a PKIX error where a proxy replaces GitHub's certificate. It now trusts the certificates this computer trusts (Windows' and macOS' own stores), as Open URL does, and if the certificate still isn't trusted it checks without it. Only the version number is read from the answer; the download page Logsift opens is always GitHub's page of that version.
- **Which tabs follow the filters:** a tab below the log that counts only the lines the filters keep (Metrics and Profile with Matching only, Messages with *Filtered lines*, a Find All made in the filtered lines) shows a filter icon after its name and a strip on top, *Only the 225 of 2,099 lines the filters keep*, with a link back to every line. Insights, Exceptions and Bookmarks say on their tab that they always cover the whole log.
- **Metrics follow the filters:** with Matching only on, the Metrics tab counts only the lines the filters keep (things that start and end by their start line, numbers by their line) and says so; turn Matching only off for the whole log. Changing filters doesn't read the log again. Insights still look at the whole log.
- **Merge CSV files:** **File → Merge Files by Time…** with only CSV (or TSV) files makes one CSV: one header with the columns of all of them (matched by name), a **Source** column with each row's file, commas between fields and quotes where needed. Rows go in time order when every file has times, else one file after the other, and the dialog says which. The result opens as an ordinary CSV tab (the tree shows the sources) and follows the files as they grow. CSV files and logs ticked together are merged as logs, as before, and the dialog says so.
- **Profile of a table:** a CSV file gets a **Profile** tab with a card per column: its kind (number, time, category, yes / no, ID, text), how many values are filled in and different, min, median, mean, 95% and max, and a chart (a histogram, the top values, or rows over time). Click a bar or a value to show only those rows. With Matching only it counts the rows the filters keep. Big files are read in blocks from all over the file, and the Profile says so. Other logs with columns: right-click a column title → **Profile of the Columns**.
- **Tables without times:** the Timeline button says there are no times, the Metrics chart numbers by row, and a CSV without a message column no longer shows its rows as "messages" in the Messages tab and Insights.
- **Format in the log's bar:** **Format: CSV ▾** (or whichever format the log is read with) moved from the status bar to the log's bar, next to the view buttons. Same list: choose another format for this file, **Plain text**, or make a new one. In a narrow window it shows just the name (*CSV ▾*).
- **No double header in CSV files:** in the Columns view, a CSV's header row is no longer shown as a row under the column titles that already name it, whether the file was detected as CSV or CSV was chosen by hand. Line numbers stay those of the file (the first row is line 2). A CSV's columns are named as in its header (*order_id*, *timestamp*) everywhere: the column titles, the tree, filters and chips, Profile and Metrics.
- **Filters on a column:** a filter can look in one column instead of the whole line: **contains**, **=** (the whole value), or **>** and **<** for numbers (*1.5 s* is more than *800 ms*). Right-click a value in the Columns view for **Show Only Rows Where Host = web-1** or **Hide Rows Where …**, or a column title for **Filter by …**; in the Filters tab, pick the column after Show / Hide / Mark. Works for CSV files, JSON logs, the built-in layouts and your own formats; such filters show as chips like *Show: Host = web-1*. **Count Values** → **Show Only** / **Hide** now filter on that column too.
- **Metrics for CSV files and other columns:** a column of numbers is a measurement over time (*duration_ms*, *bytes*, the access log's *size*; units from the value or the column's name), and a column with a few values (*status*, *host*) shows how many rows have each value per minute (or per second, per hour). In a CSV file, the Messages tab and the numbers in messages read the message column only, so *Request … took # ms* is one measurement for all levels (numbers in a CSV's messages were missed before).

## 1.3.0

- **Heap dumps check the room first:** before the JVM writes a heap dump on its machine (over SSH, or for a JVM on this computer), Logsift compares the heap in use with the free space there. A folder without room, or a `/tmp` in memory, is refused before anything is written, and Logsift asks for another folder on that machine. Heap dumps and histograms of big heaps get time to finish (an hour, a quarter of an hour) instead of failing while the JVM is still writing.
- **Safe around production:** each action that reaches a running JVM says what it costs the service where you start it (thread dumps, histograms, heap dumps, each profiling mode, reading or copying a dump on a server), and the README lists them all in *What Logsift does to a running service*. Logsift no longer removes any file on a server: heap dumps, recordings, copies and stopped copies stay where they are, and Logsift says where. Fixed on the way: a heap dump or recording left on a server is readable only by your login user (it was world-readable while copied); a Flight Recorder recording ends by itself even if Logsift is gone; opening a Profile tab no longer loads async-profiler into the JVM; a histogram without a full GC never falls back to one; method tracing names one class (`com.*.*` could stall the JVM); copying a heap dump from a remote log asks first, with its size; a copy between servers refuses a name that is taken and adds nothing to the other server's known_hosts.
- **Heap dumps over a JMX port:** **Save Heap Dump…** works for a JVM reached through its JMX port. The JVM writes the dump on its own machine; Logsift offers to copy it here over SSH (the host filled in) and opens it, or says where it is; the dump stays there. A JVM on this computer writes it straight to the file you chose.
- **GC logs explained:** open a Java GC log (Java 8 to 25; G1, Parallel, Serial, CMS, ZGC, Shenandoah) and **Analyze GC** says how much of the time the program stood still, the longest pauses and why, whether the memory left after GC keeps growing, and what went wrong (full collections, evacuation failures, concurrent mode failures, allocation stalls, System.gc() calls, pauses that waited for the machine), each with what to try. Charts of the heap, pauses, allocation and time in GC zoom together; a click shows the line in the log. Also **JVM → Open GC Log…**.
- **Find in a zip:** a zip's tab has a **Find in all files** box (Ctrl+F goes there) that searches every file in the zip, whatever it is called (a `.csv` too, not only `*.log`). Search in Folder from a zip's tab searches that zip.
- **Folder search results:** **Filter results by file name**, and **Expand All** / **Collapse All**, above the results.
- **Find All in the filtered lines:** while the log shows only the lines its filters keep, Find All finds in those lines, and follows the filters as they change.
- **Clear All** in the log's bar, lit while anything is set: removes every filter, the time range and what the tree hides, and closes the find bar and the Find results.
- **Attach over JMX works in the installed app:** connecting to a JMX port failed with "Failed to retrieve RMIServer stub" because the app's bundled Java left out the part that looks up a JMX port.
- **CSV files no longer show empty rows:** rows with a field or two more or less than the header (a trailing separator, a missing last value) are shown in their columns instead of as empty-looking lines, and the header row shows its names in the columns. In a CSV without a message column, a line that isn't a row starts at the left instead of far to the right.
- **Open URL behind a company proxy:** certificates the computer trusts (Windows' and macOS's own stores) are trusted too, so a proxy's certificate no longer stops a download. When a certificate still isn't trusted, Logsift asks whether to open it anyway without checking, once or always for that server.
- **Heap dumps explained:** open a `.hprof` file (File → Open, JVM → Open Heap Dump…, the start page, or drop it in) and Logsift says in plain sentences what fills the memory: *"One HashMap (20,000 entries) in static SessionCache.CACHE holds 1.2 GB (85% of the heap). Mostly 20,000 × Session, 616 bytes each with what they hold."* **Why is it alive?** shows the chain of references from a GC root (a static field, a local variable in a thread, …) to any object. **Biggest objects** lists each object with what it holds, biggest first; **Classes** has every class with its objects' size and what they hold. Memory only weak or soft references reach is set apart: it isn't a leak. Sizes match the JVM's own. Big dumps keep their index on disk, not in memory, at most about the dump's size: a 12 GB dump with 223 million objects opens in about 2½ minutes with the app's usual 2 GB of memory (Logsift checks there is enough free disk first). Sizes are right however the JVM laid out its objects (compressed pointers or not, ZGC, compact headers), worked out from the dump. A heap dump saved from a running JVM opens by itself.
- **Wasted memory** in a heap dump: copies of the same strings (*"ACTIVE": 20,001 copies, 469 KB, in Session.status*) and empty or mostly empty collections (*20,000 empty ArrayLists in Session.tags, 1.5 MB*), each with the field that holds them and what to do about it. When it is a lot, it is a finding on the first page.
- **Two heap dumps compared:** **Compare with Another Dump…** in a heap dump (or JVM → Compare Two Heap Dumps…) says what grew between an earlier dump and this one, and where it is kept: *"HashMap in static SessionCache.CACHE grew by 800 MB (200 MB → 1 GB). 5,000 entries → 20,000 entries."* Every class, before and after, is listed too.
- **Heap dumps read on a server:** JVM → Open Heap Dump on a Server… reads a dump where it is, over SSH, on a Linux or macOS server with whatever Java 8 or later it has; only the answers come over. Logsift says what it takes there (disk, memory, time) before starting, runs at low priority, and keeps going if the connection drops. Its index is temporary files that go when the reader ends (the tab closes, or 30 idle minutes); nothing else is removed there. **Copy to Another Machine…** moves a dump off a production server first (server to server when it can, else through this computer) and reads it there.
- **The heap as a map:** a **Map** view of a heap dump shows each object as a box as big as what it holds, with what it holds inside it, through collections to what is kept in them, and many objects of one class together (*20,000 × Session*). Click for why it is alive, double-click to go in. It draws in about a second for a 12 GB dump.
- **Matching only** turns off by itself when the only filters left are Color filters (they color lines, they don't hide any).
- **Cancel** now stops copying a heap dump from a server.
- **A heap dump's threads:** **Threads (N)** opens them in the Threads view, with their states and stacks at the moment of the dump.
- **From an OutOfMemoryError to its heap dump:** right-click the line (or use **Open Heap Dump** on the known problem in Insights) and the dump the JVM wrote (`Dumping heap to …`) opens, found where the log says or next to the log, and copied over SSH for a remote log.
- **Find bar (Ctrl+F):** finding in a log is now a bar at the top of the log, as in most programs. Matches light up as you type, Enter and Shift+Enter go to the next and previous one, and it counts them ("3 of 1,240"). **Find All** lists them below the log, **Filter ▾** turns the search into a filter, and Esc closes it.
- **Each log has its own bar:** Find, Filters, the filters that are on as **chips** (click to turn one off, ✕ to remove it), Wrap, Columns, Tree, Timeline, Follow and Reload (**▾** for reloading automatically). Each log keeps its own view settings; the last choice is the default for the next log.
- **Start page:** with nothing open, the window offers Open Log, Open Folder, Open Remote, Open URL, Attach to a JVM, Open Heap Dump, Open Thread Dump and Open Profile, and your recent files and last session. With logs open, **+** after the tabs shows it in a tab.
- **No toolbar on top:** opening files, remote logs, Search in Folder and Settings are in the menus (with their shortcuts), so profiles, heap dumps and folder searches get the whole window. The update notice is in the status bar.
- Adding a filter from the right-click menu no longer switches the panel below to Filters: it shows up as a chip.
- **Full pools are found when their threads wait on the database:** threads waiting for a pool's connection or reading a JDBC or HTTP answer count as busy, not idle.
- **Python thread dumps:** `py-spy dump` output and `faulthandler` dumps (also inside a log) open in the Threads view, with thread names, idle or active (and who holds the GIL), and stacks.
- **Known problems in Insights:** about 30 problems that look the same in every log (a connection pool that ran out, a full thread pool, out of memory, GC pauses, untrusted certificates, timeouts, database deadlocks, Kafka rebalances, a container killed for memory, gunicorn worker timeouts, unhandled asyncio errors, Celery retries…), each with **What to Try**.
- **Metrics:** a new tab with how long things that start and end took (matched by the job or request they name, or by thread), the ones that **never ended**, and the **numbers in messages** (durations, sizes, counts) as charts over time with their slowest lines. Insights reports what never ended and when a measurement spiked.
- **Open the source of a stack line:** in the Exceptions tab, or right-click a stack line → **Open … in Editor**. The file is found in your source folders (Settings → Source Code) and opened at the line in IntelliJ IDEA, PyCharm, Visual Studio Code or a command of your own.
- **Exceptions by root cause:** a new **Exceptions** tab groups Java stack traces and Python tracebacks by their root cause and where it was thrown in your own code (framework and library frames are skipped), with counts, first and last time, the stack with your frames highlighted, what wrapped it, and ◀ ▶ through each time it happened. Insights names the most frequent ones.
- **Find All from the right-click menu:** select text, right-click → **Find All “…”**, next to Show, Hide and Mark lines with it.
- **Follow a request:** right-click a line with a trace or request ID (or select any text, or press Ctrl+Shift+R) → **Follow**. The new **Request** tab lists its lines in order, across threads and merged files, with the time since the line before and the longest wait marked. Recognizes `traceId=`, `requestId`, `X-Request-Id`, JSON keys, `[app,traceId,spanId]`, `traceparent` and UUIDs. **Lines of its threads in between** adds the lines its threads wrote while working on it. **In: All open logs** or **Folder** follows it through several files (inside zips and `.gz` too), in one order by time with a File column.
- **Thread dumps, explained:** JVM → Open Thread Dump… reads jstack and jcmd output, `kill -3` dumps inside a log (also with a time in front of each line), and `jcmd Thread.dump_to_file` files (plain and JSON, with virtual threads). A log with dumps in it offers **Analyze Threads**.
- **What stands out first:** deadlocks (monitors and ReentrantLocks), threads queueing for a lock and who holds it, threads stuck in one place across dumps, threads using a lot of CPU, pools with every thread busy, and a growing thread count. Each with **Show threads**.
- **Threads view:** grouped by pool or by identical stack, filtered by state or text. A thread's stack shows the lock it waits for and who holds it, and who waits for its locks, as links. **Timeline** shows each thread's state in every dump; **Compare** shows what changed between two dumps.
- **Attach to a running JVM** (JVM menu, Ctrl+Shift+J): on this computer, or on a server over SSH. Take a dump, or record several some seconds apart. On servers, jcmd is found by itself (or give the JDK folder); without JDK tools, async-profiler is copied to the server's /tmp and used instead. JVMs of other users are reached with sudo (Logsift asks for the password if needed).
- **Profiling:** flame graphs with async-profiler (Linux and macOS JVMs) or Flight Recorder (any JVM, Windows too) of CPU, wall-clock time, allocations, **live objects** (memory leaks), locks, **native memory** and **native memory leaks**, native locks, **calls of a method** and **slow calls** (over a time you give), **hardware events** (Linux), or **everything at once** (one run, several views; it opens on a view with data, and says which came back empty). Per-thread graphs. Zoom, highlight methods; right-click for **callers** of a method, or only (or none of) the stacks through it; turn the graph upside down. Every run stays in the tab: **compare** two (red grew, blue shrank). Save and open profiles (collapsed stacks and `.jfr` files).
- **A log knows its JVM:** a bar above a log names the JVM writing it, with Threads, Profile and Heap buttons. It is found by itself on this computer and on the server of a log opened over SSH (the JVM that has the log open, the one linked before, or the one the log names). For a log on a shared drive or copied from a server, Logsift reads what the log says about itself (Spring Boot's startup line: program, host, process id) and the drive's server, and offers **Find Its JVM…** with them filled in. **JVM → Link This Log to a JVM…** links any log by hand. Links are remembered by program for the log and its folder, so they survive restarts and new versions.
- **Thread names connect logs and dumps:** right-click a line → **Show Thread in Threads** shows its stack in a dump (names the log cut short still match); **Lines in Log** in the Threads tab shows only a thread's lines.
- **JMX port:** attach to a JVM through `-Dcom.sun.management.jmxremote.port`, from anywhere, without SSH: thread dumps, heap histograms, and Flight Recorder profiles streamed back over the port.
- **Spring Boot's log layout** is recognized (time, level, process id, application, thread, logger, message).
- **Zip and .gz files:** drop a `.zip` and it opens as a tab: its folders and files as a tree (zips inside it too), with sizes and a filter. Open files as logs, **Merge by Time**, or **Search in All Files…**; a zip with one file opens it right away, and a `.gz` opens directly. A file from a zip is named by its place in it (`bundle.zip/logs/app.log`) and is like any log: bookmarks, filters and format are remembered, and it comes back from Recent files and the last session. Folder search opens hits in zips the same way.
- **Open URL** (File menu, Ctrl+Shift+U): download logs over `http`/`https`, with a user and password or a token. One opens in a tab; several are downloaded together and searched.
- **CSV files as columns:** a header row names the columns; commas, semicolons, tabs or bars, and quoted fields. Time, level and message columns are recognized, and other columns go into the tree beside the log, where a value can be hidden. Also in the format menu.
- **Folder search looks inside zips inside zips** (up to 5 levels), and inside `.gz` files and rotated logs (`app.log.1`) in a zip. Double-clicking such a line unpacks it through each level. The count of files with hits no longer counts each entry of a zip as a file.
- **The heap:** what fills it, by class, and what grew between two histograms (where memory leaks). Save a heap dump (`.hprof`), also from a server over SSH.

## 1.2.0

- **Your own log formats:** drop a log file and Logsift works out its layout and how its times are written, or paste your log4j / logback / Python logging setup (a pattern, or a whole `logback.xml`, `log4j2.xml` or `log4j.properties`). Properties in the config (`${LOG_PATTERN}`, `${sys:PID}`) are filled in, Log4j 2 `.properties`, `.yaml` and `.json` configs work, and with several appenders the layout your log fits is used. A live preview shows how lines split into columns.
- **Format in the status bar:** shows how the current log is read. Click it to choose another format for that file if the detected one is wrong.
- **Tree of loggers:** loggers (or threads, components, hosts) as a package tree beside the log, with line counts. Uncheck a branch to hide its lines, double-click one to see only it.
- **Settings** (Ctrl+, / ⌘,): font, tab width, encoding for text that isn't UTF-8, how often files are checked for changes, reopening the last session, and more.
- Levels written as `E`, `ERR`, `error` or `SEVERE` count as errors in your own formats (colors, error marks, F8, level chips).
- **Open from WSL** (Windows): opens your Linux home folder.
- **Insights:** a new tab that shows at a glance what is going on in the log: error bursts (and when), new errors and when they began, silences, restarts, and noisy messages, each with buttons to go there, show or hide it. It fills in by itself and its title counts the problems.
- **Menus with icons, regrouped:** a new **Go** menu (Go to Line/Time, next error, bookmarks), and check marks on everything that turns on or off. New toolbar buttons for the tree of loggers and the timeline, and Settings (⚙).
- **Splash screen** while Logsift starts.
- **Windows: Open with Logsift** on the right-click menu of files and folders, and in the Open with list of `.log`, `.txt` and `.out` files. The installer no longer takes over `.log` files (their icon and double-click stay as they were). On macOS, Logsift is likewise offered in Open With without becoming the default.
- **Logs on network shares:** the window no longer freezes while a big file on a share is read. Lines on screen load in the background and appear as soon as they arrive.
- Clicking a long wrapped line that is partly off screen no longer scrolls the view.
- **Hide columns:** right-click a column header → *Hide … Column*, or tick columns on and off. A **N columns hidden** chip in the header lists them, and **Show All Columns** brings them back. Remembered per format.
- **Select text in the Columns view**, not just whole lines: drag across cells or the message, double-click a word.
- **Details shows the whole entry:** a line with its stack trace, not just the one line. Select text and Details shows just that: several lines, or part of one.
- **JSON in Details:** a **Text | JSON** switch pretty-prints the JSON in a line or selection (also JSON in the middle of a message), opening up JSON written inside strings. Switch back to see the text as it is.
- **Loading indicator:** lines still being read from a slow disk or share show as gray bars with a *Reading from disk…* badge, and an empty log being opened says so, instead of a blank view.
- **Config import reads more:** Log4j 1.x XML (`<param name="ConversionPattern" …/>`), java.util.logging (`SimpleFormatter.format`), every formatter in a Python config with its `datefmt`, and `basicConfig(…)` / `Formatter(…)` in Python code.
- **A config with several layouts makes a format for each** (named after the appender), instead of asking which one. Each log uses the one it fits.
- **Windows installer:** a new build installs over the one already there (snapshots used to need an uninstall first), and a running Logsift is closed before files are replaced or removed.
- Logsift now exits fully when its window is closed (it could stay running in the background).
